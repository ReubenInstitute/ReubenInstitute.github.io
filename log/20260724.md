# 24 Jul 2026 – DeepSeek 3 Expert – Java calendar library ported to JavaScript, live demo page built

_Code, Web_

The Hebrew Clock project began not with a design document but with a direct translation of an existing Android library into JavaScript, and by the end of the session a fully functional live demo was running in the browser.

### Java‑to‑JavaScript port

The Institute’s Android app contained a complete Hebrew calendar and clock library written in Java. The decision was made to lift that code verbatim into ES6 modules — no redesign, no added abstractions, just a mechanical port that preserved the original class names, method signatures, and internal arithmetic. Every module was made self‑contained: `Date.js` for Gregorian date and time, `HebrewDate.js` for the Hebrew calendar and seasonal time representation, `Sun.js` and `Moon.js` for astronomical calculations, `HebrewHoliday.js` for festival detection, `TorahPortion.js` and `TorahSchedule.js` for the weekly readings, and the full set of geographic, numeric, and naming utilities. The only external dependency was Handlebars, kept strictly for templating and never allowed to leak into the logic layer.

### Live demo page

A single `index.html` was built to exercise the entire library in real time. The page renders two analog clocks side by side — a standard 12‑hour civil clock with uniform ticks, and a 24‑hour seasonal Hebrew clock whose day and night arcs expand and contract with the location and date. Below the clocks, full Gregorian and Hebrew monthly calendars are displayed, complete with Hebrew date numerals, holiday names, and a Torah column showing the Shabbat portion for each week. Sunrise, sunset, moonrise, and moonset times are shown for the current location.

The clock faces were drawn with a strict separation of concerns: the HTML structure is defined entirely in Handlebars templates; the JavaScript classes only manipulate existing DOM elements via IDs and classes. Tick marks are generated programmatically by the clock constructors and styled through CSS custom properties — the `--angle` variable sets rotation, and all positioning and colouring lives in the stylesheet. The Hebrew clock’s day and night arcs are handled by a single `nth‑child(n+13)` rule scoped to a dedicated ticks wrapper.

Several rendering bugs were encountered and fixed during the build. The `DaySpan` and `HebrewDateTime` exports were missing from their respective modules and were added. The `Date.today` method wasn’t imported into the Hebrew clock, causing a silent failure. Ticks initially rendered at the centre of the clock face because the CSS transform lacked a `translate(0, -110px)`; the transform was moved into the CSS and combined with the `--angle` variable. Handlebars `{{#each}}` loops were generating duplicate ticks that overlapped, cutting the visible count from 24 to 22 — the loops were removed entirely, leaving only the JavaScript‑generated ticks. The day and night arc angles were wrong because the fraction formula used `i/D` and `i/N` instead of dividing by 12 to spread the 12 hours evenly within each arc. Finally, the `nth‑child(n+13)` selector for night‑tick colouring was counting all children including the clock hands and centre cap; a wrapper `<div class="clock-ticks">` was added to scope the selector correctly.

### Epoch‑day system and HebrewTime

Underpinning both calendars is a single continuous epoch‑day integer, shared by `Date` and `HebrewDate`. This allows any Hebrew date to be converted to a Gregorian date and vice versa with simple arithmetic, and it keeps all calendar math free of lookup tables or external references. The Hebrew clock’s time is represented as a float hour from 0 to 24, where 0 is sunset and 12 is sunrise. This was carried over unchanged from the Java library. Display logic converts the float into 1‑based per‑period hours — the first hour after sunset is hour 1, not hour 0, and midday (hour 18) and midnight (hour 6) mark the start of the seventh hour of their respective periods.

At the end of the session the entire library was self‑contained, the demo page was fully operational with both clocks and both calendars animating in real time, and the system was ready to be pushed to the Institute’s GitHub Pages front‑page or used as a standalone web application.
