# 19 Sep 2026 – DeepSeek 4.1, Claude (Code) Sonnet 5 – GitHub migration: audio repos, book naming, code repos, Studio from its repo, and the Java libraries

*Code, Libraries, Media, Studio, Android*

The goal was simple to state: start using GitHub consistently. Code and audio that had lived only on a local disk would move into repos gradually, with the rule "getting it running first, correct organization later". What followed was a long day of merging, renaming, pushing, and fighting a proxy, until every folder in `/root/WORK` that mattered was a real clone in sync with GitHub.

### Ground rules

A few conventions were settled before anything was moved:

* Commit even the tangled or misplaced pieces, and split them later.
* No Git LFS yet.
* Commits are authored as Claude Code, with a `Co-Authored-By` trailer.
* Code and content go in separate commits.
* Projects use shared libraries through `PYTHONPATH`, with no system changes, until pip or deb packages come later.
* Verify the new setup first, then remove duplicates and old copies.

The environment was a DigitalOcean test VPS whose root disk was about 89% full. A 100 GB volume was attached at `/mnt/data` (about $10 a month) for the heavy work, and pushes used a token placed in `/root/claude.txt`.

### The chapter audio

Three public repos from `grahame` (`Schmueloff---Torah`, `---Writings`, `---Prophets`) were merged into one, keeping their history. `git filter-repo` moved each into its own subfolder, and the three were merged. The result was 929 mp3 files (187, 362 and 380), five original commits by Grahame Bowland, about 1.2 GB. The largest file was under 100 MB, so no LFS was needed.

All 39 folders and 929 files were then renamed to the official spelling, `NN-slug/slug-chapter.mp3` (for example `Torah/01-bereshit/bereshit-01.mp3`), using the CSV's global numbers. They were pure renames, so history follows, and the final commit was `e4974a9`. The repo was later renamed `audiobible-shmueloff-source`.

The lesson came right after: renaming everything made git re-send all 1.2 GB. The cause was `pack.useSparse`. Pushing with `-c pack.useSparse=false` sent 26 KB.

### Book naming

`Scriptures/csv/books.csv` got a pass of its own. The surname is spelled **Shmueloff** everywhere, matching the BnF authority form as DeepSeek reported (not verified on our side), while upstream links keep Grahame's `Schmueloff`. The transliteration rules:

| Hebrew | Written |
|---|---|
| ה | h |
| ח | ch |
| soft כ | kh |
| hard כ / ק | k |
| soft פ | f |
| צ | tz |
| ת, ד, ג (soft) | plain t, d, g |
| soft ב | v |

Gemination is written out, so `Chaggai`, `Tehillim`, and also `Vayyikra`, `Bammidbar`, `Chabbakkuk`, `Iyyov`, `Daniyyel` and `Divrei Hayyamim`. In the columns, `latin_name` is the traditional English Bible name, `english_name` is our transliteration, and `hebrew_name` is the Hebrew; the field names were not renamed. The corrections covered Melakhim, Yechezkel, Ovadyah, Mikhah, Nachum, Chabbakkuk, Tzefanyah, Zekharyah, Shir HaShirim and Divrei Hayyamim Alef/Bet, plus the slugs, and the Hebrew of Shoftim was fixed (the dot goes on a full vav with a holam).

### The verse audio repos

Four more audio repos were created and verified with fresh clones and checksums against the `Studio/audio` folders:

| Repo | Files | Commit | Note |
|---|---|---|---|
| `audiobible-shmueloff-original` | 4,830 | `05bf072` | 771 MB |
| `audiobible-shmueloff-darkknox2` | 4,800 | `239ed6d` | `test.py` was excluded |

The proxy was the enemy here. Large single uploads ran at about 50 KB/s or hung, while small ones ran at about 18 MB/s. The fix was to upload in batches of 50 files to temporary branches, then build the single commit through the GitHub API and delete the temporary branches. That is saved as `/root/upload_audio_repo.py`, and it is resumable. My first attempt used cumulative batches that resent everything, and it took a while to find the cause.

### What the tests showed

`Scriptures` served 969 Bible pages, and only the 23 Shoftim pages differ from the original. About 3,046 Talmud pages return 404 and 9 return 500, and that happens in the original commit too. `StyledScriptures` now loads all 54 parashot with 5,737 verses, where the original code loaded zero verses for 48 of them. The psalm structure is identical (2,527 verses), but the text differs for 110 psalms because `Hebrew.normalize` is no longer called.

One mistake was caught here: the first comparison used a backup taken after the CSV edits, so it could not show the CSV's effect. It was redone against the original commit.

### Studio from its repo

The next goal was to make `Studio` work directly from its GitHub repo, with the audio pulled in from the separate repos. The repo had only an initial commit, and the local folder had real edits. They went up as separate commits: the 9 code files and `styles.css`, the 13 templates (English LTR redesign), a new font, and the five `audio/*.csv` indexes. The 77-byte test `csv/alignment.csv` was dropped.

The audio became submodules (`audio/cloned`, `original`, `english`, `titles`), and a fresh recursive clone from GitHub brought down all 9,829 mp3s, matching the originals byte for byte. `test.py` moved out of the audio repo to the Studio root as `rebuild_cloned_csv.py`, unchanged, and it is stale against the current `AudioBible` API. `/root/WORK/Studio` is a real recursive clone, not a symlink.

Getting it to run took a few fixes: `python3.12-venv` and a `/root/venv` with `elevenlabs`, the imports renamed to `Parashot` and `Psalms`, the Flask template folder name, and the parashot list page, which was passing the wrong data and had broken links. The last commit of that stretch was `e627086`.

### A mistake, fixed at once

A `push -u` with the token in the URL saved the token in each Android folder's `.git/config`. It was caught immediately and removed, and confirmed never committed or pushed, but revoking the token at the end of the migration is still the right move.

### Housekeeping and the Java libraries

The local folders were renamed to match their repos: `HebrewDateApp` to `HebrewDate-android`, `PsalmsApp` to `Psalms-android`, `UsbThing` to `UsbThing-android`. The standalone `/root/WORK/java` was deleted after confirming its sources were already committed in HebrewClock, and the Java sources moved to `Libraries/java` (63 files). `HebrewDate-android`'s Makefile now uses `../Libraries/java`, and the APK builds and signs. `HebrewClock/java` was removed, and `make test` in `Libraries/java` now skips `Clock/`, which needs Android's `Bitmap`.

The fixes that came along:

The psalm video export then worked on the VPS, a good end-to-end check that the `ffmpeg-python` fix, the `assets/` submodule and the shared Python modules work together.
* **Studio repo:** `requirements.txt` added, `build/` put in `.gitignore`.

The public repo `ReubenInstitute/Studio-assets` was created with 118 files (`mp3`, `mp4`, `jpg`) and attached as the submodule at `Studio/assets`. The push used a batched upload script variant, and a diff against the original upload showed no differences. `back.mov` (160 MB, over GitHub's 100 MB limit) and `x.py`, `y.py` and `z.py` were moved to `/root/WORK`.

### Disk, storage and LFS

`/root/.arduino15` (7.6 GB) was deleted, taking the root disk from about 1 GB free to about 8 GB. The `/mnt/data` volume was checked first (everything on it was on GitHub, including Grahame's history in `src`), then emptied and unmounted, ready to be deleted.

LFS came up again. The free-tier limits were explained (1 GiB storage and 1 GiB monthly bandwidth per org), along with the likely cause of the earlier pointer files, and LFS was put on hold with nothing changed.

### Where it ended

All the git folders in `/root/WORK` were in sync with GitHub with no uncommitted files: `Libraries`, `MediaLibraries`, `Scriptures`, `StyledScriptures`, `Studio`, `HebrewClock` and the three Android repos. The notes for future sessions were updated with the repo map, the run command and the workflow lessons.

What is still open:

The doubled vowel marks in the psalm markdown files are probably deliberate. `Libraries` is public, which I'd suggested making private, and there has been no answer yet.
* **Security:** Studio now runs on `0.0.0.0` with `debug=True` and no login, so if it is reachable from outside the network, turn debug off or add firewall rules. The push token in `/root/claude.txt` should be revoked when the migration is done.
