# 18 Sep 2026 – DeepSeek 4.1, Claude (Code) Sonnet 5 – HebrewDate Android app: shared library, screens, clock, free/pro, and widgets

*Android, Libraries, Code*

The HebrewDate app started the week as a small Android project carrying its own private copies of the date classes, and ended it as a clock app with three screens, a Hebrew month calendar, a Jerusalem clock, light and dark themes, a free and a pro mode, and four kinds of home‑screen widget. It was built in plain Java with a Makefile, one task at a time, in fresh Claude Code sessions that knew nothing but the task at hand, while DeepSeek supervised from outside, holding the plan and the clarifications but never the code. Messages went back and forth between the two until they converged.

### Moving onto the shared library

The first task was to stop the app from owning its own copies of things that already lived in the shared `../java` library. `Date`, `Time`, `HebrewDate`, `HebrewNumbers`, `JewishHoliday`, `DaySpan` and `HourSpan` were deleted from the app, both at the root and under `app/src/main/java/...`. The Makefile’s `app` target now symlinks `Date`, `Hebrew`, `HebrewDate`, `Astro`, `Geo` and `LocalHebrewDate` from `../java`. `Astro` and `Geo` were not on the original list; they were needed only because `Date/DateTime.java` imports them.

The library uses `List.of`, which forced `minSdk` up from 24 to 30 — a choice put to us, and accepted. `DateWidgetProvider`, `DateNotificationService` and `MainActivity` were ported to the new API, with the date, holiday and gematria formatting written inline and no new classes. The old `HebrewDateApp/java/` folder was left untouched on request, so its `Main.java` no longer compiles.

`javac` against `android.jar` compiled the result, with only the generated `R` class missing, and a throwaway check produced correct Hebrew dates and holidays (Rosh Hashanah, Purim). The full `gradle assembleDebug` could not be verified, because Gradle hangs in this sandbox.

### Porting the clock to Java

The Python `Clock.py` and `Display.py` were ported to exactly two Java files, `java/Clock/Clock.java` and `java/Clock/Display.java`, with `StandardClock`, `HebrewClock` and `VisualBand` as nested classes of `Clock`. Text drawing uses `android.graphics` directly, as chosen. The near‑duplicate draw methods share one helper.

Against the Python originals, the drawing primitives came out pixel‑identical, and so did both clocks (excluding the digits). Band angles, colours, stripe flags, seasonal marks and hand angles matched in three test cases. The hour digits themselves need a device, and remain unchecked.

The rules for this port were strict, and were followed:

* Existing library files are not modified. The md5 checksums are identical before and after, and the `java/Makefile` was not touched.
* No extra classes or interfaces in the library, no format class, no helper classes.
* No PNG export. The dead `drawHalakhicBands()` call and the `__main__` demo were left out.

One accepted side effect: plain `make test` in `java/` now needs the Android jar on the classpath.

```
CLASSPATH=<android-34 android.jar> make test
```

### Restructuring the app

The handler classes were renamed: `BootReceiver` became `BootHandler`, `DateWidgetProvider` became `WidgetHandler`, and `DateNotificationService` became `NotificationHandler`. The manifest and every reference were updated, and the Makefile’s `app/` symlinks regenerated.

`MainActivity` became `MainScreen`, and `CalendarScreen` and `SettingsScreen` were added. They are separate activities with no shared base class. Each layout carries its own copy of the full‑width three‑button menu (Main / Calendar / Settings), with the current screen’s button disabled. Switching has no animation, using `FLAG_ACTIVITY_NO_ANIMATION` and a theme whose `windowAnimationStyle` is `@null`. The title bar was removed with a `NoActionBar` parent theme. The notification toggle moved to `SettingsScreen`, while the start‑the‑service‑on‑launch logic stayed on `MainScreen`.

### The calendar and the clock on screen

`CalendarScreen` shows a Hebrew month grid from the library’s `HebrewMonthCalendar`, with gematria day numbers and today highlighted. `<` and `>` step by Hebrew month, changing the year at Tishrei and handling Adar I/II in leap years. Whether to flip it to Sunday‑on‑the‑right was asked, and never answered.

`MainScreen` shows the library’s `StandardClock` for Jerusalem with the `LOCAL` custom, drawn into a 480px `ImageView` and redrawn every second. The `Clock` package had to be added to the Makefile’s symlink list first. Here a limitation surfaced: the library hard‑codes UTC+3, so the sun, moon and halachic rings are an hour off in winter, while the hands stay correct. Fixing it needs a library change, which had been ruled out, so it stayed.

While tracing the clock, we found the second hand missing. In Python the constants and angle were still there but the draw call had been removed; the Java port had never had it at all. Length, tail, `secondHandAngle()` and the draw call were added to Java’s `StandardClock`. The Python draw line (`python/Clock.py:548`) was never back‑ported.

### Settings, themes and pro

`SettingsScreen` gained four radio groups for the custom: day definition (GRA/MA), dawn, misheyakir and nightfall (25 options, in a scroll view), saved by enum name. A preset spinner (Manual plus 10 presets) sets all four at once, and follows manual changes by switching to the matching preset or to Manual. `MainScreen` builds a fresh clock from these values on every resume.

For themes, `Clock/Palette.java` holds the chrome colours and the four night‑family colours as `LIGHT` (today’s values) and `DARK` (a first cut). The semantic band colours stay fixed, and the dark dial is `0x2A2D34`. `Display.drawCurvedChar` takes a digit colour, and the app picks the palette from the system night mode, with a `values-night` theme. The dark palette is unchecked: the deepest night watch has low luminance contrast against the dial, and the `DAWN` band sits at about 2:1.

Free and pro modes came next. The app starts free: no clock and no custom controls, but the calendar and the notification switch stay, and the main screen shows today’s Hebrew date and holiday instead of a clock. Tapping the main screen seven times enables pro. `Pro.java` was in‑memory only at first, meant to become the Google Play entitlement check. The seven‑tap unlock must be removed or limited to debug builds before a Play release.

### Home‑screen widgets

The last task was a month‑calendar widget and pro‑only clock widgets. Exploration first: the app had one 2x1 date widget, and pro was an in‑memory flag that reset on restart. Three problems showed up. Android clamps `updatePeriodMillis` to 30 minutes, the old `triggerUpdate` never re‑ran `onUpdate`, and widgets cannot tick every second.

The decisions were: three fixed clock sizes (2x2, 3x3, 4x4), a persisted pro flag with a "Pro only" placeholder for free users, per‑minute clock refresh, and the date widget refresh fix included. `WidgetHandler` was renamed `DateWidgetHandler` first. My proposed `WidgetUpdater` class was questioned, and dropped in favour of a small base class. Then the whole plan was approved, with old‑widget artifacts to be ignored.

What was built:

* **`TimedWidgetHandler`** — the new base class. Each widget arms its own alarm, at midnight for date and calendar and every minute for the clock. A static `triggerUpdate` redraws all widgets, and `NotificationHandler`, `BootHandler` and the pro gesture call it.
* **`Pro`** — now persisted in `app_prefs`, and takes a `Context`.
* **`HebrewMonths`** — month stepping moved out of `CalendarScreen` and shared with the widget.
* **`ClockSettings`** — builds the clock from saved settings, shared by `MainScreen` and the widgets.
* **`CalendarWidgetHandler`** (4x3) — the Hebrew month with ‹ ›, today highlighted, and tap‑the‑title for today.
* **`ClockWidgetHandler`** with `ClockWidget2/3/4` (300, 420 and 480 px) — they open the app when tapped and show the placeholder when free.
* **`Clock` library** — a public `showSecondHand` flag (default `true`) that hides the second hand in both clock types. The clock widgets set it to `false`.

New layouts, provider XMLs, strings and four manifest receivers came with it.

### Build and what remains

Gradle was removed in a separate session, so every build here went through `make`. The APK built cleanly and the Makefile copies it to `/var/www/html/public/HebrewDate-0.1.apk`. The widget build was made with `PUBLIC=/tmp/pub/`, so that one is not in the public folder.

Nothing has been run on a device or emulator: not the menu, calendar, clock, themes, custom settings, pro unlock or widgets.

Still open:

* The Python back‑port of the second‑hand draw call and the palette.
* The winter timezone shift, which needs a library change.
* The calendar direction question.
* The pro unlock, before any Play release.
* The clock drawing on the UI thread every second, the first thing to move to a background thread if it stutters.
* The date `TextView`s on `MainScreen`, which are never filled in.
* Widget alarms are inexact, so refreshes can slip by a minute or more, the minute hand still moves slightly with the seconds, and there are no widget preview layouts, so the picker shows only descriptions.
