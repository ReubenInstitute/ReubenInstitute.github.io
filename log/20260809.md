## The Parashah enum and the holiday shift

We extracted the 54 regular weekly portions into a `Parashah` IntEnum, confirming the count book‑by‑book. One correction: `VEZOTH_HABERAKHAH` (Deuteronomy's final portion) was missing from the tables entirely, folded into the Simchat Torah holiday slot — we appended it as member 54.

We then identified which entries in the old tables were *not* parashot: the Four Special Portions (Shekalim, Zachor, Parah, HaChodesh), HaGadol (a label only), and nine holiday‑replacement entries (Yom Kippur, Pesach I/VII/VIII, Hol HaMoed Pesach/Succoth, Succoth I, Shemini Atzereth, Rosh Hashanah I) plus Shavuot II. These were extracted into a separate `HolidayReading` enum.

The critical decision was to shift the holiday reading values to 55–64, leaving 1–54 for the parashot. This created an unambiguous namespace: any number ≤54 is a parashah, any number ≥55 is a holiday. No additional flags or fields are needed.

## Special Shabbat types – ShabbatType and ShabbatChodeshType

We split the remaining special‑Shabbat entries into two enums based on frequency: `ShabbatType` (eight annual, calendar‑fixed occasions — Shekalim, Zachor, Parah, HaChodesh, HaGadol, Shuvah, Chazon, Nachamu) and `ShabbatChodeshType` (two monthly‑recurring conditions — Machar Chodesh, Rosh Chodesh). Both have `NONE = 0`.

We added three properties to `HebrewDate`:

- `shabbat` – returns the `HebrewDate` of that week's Saturday.
- `shabbatType` – computes by building anchor dates (1 Nisan for HaChodesh, 9 Av for Chazon/Nachamu, 13 Adar for Zachor, etc.) and walking to their own Shabbat via ordinal arithmetic. The key fix was using `dayofweek % 7` so Saturday anchors map to 0, avoiding the off‑by‑week bug that had plagued earlier attempts.
- `shabbatChodeshType` – checks whether the Shabbat falls on Rosh Chodesh or Machar Chodesh.

Both properties return Python `None` when nothing applies; the `NONE = 0` members are kept only for cross‑language parity. We added name‑lookup functions (`shabbatTypeNameEN/HE`, `shabbatChodeshTypeNameEN/HE`) as plain list‑indexed functions without defensive checks.

## YearType and the keviyah mapping

The old `getYearType()` function used three pieces of information to return a number 1–14: the weekday of Rosh Hashanah, the year‑length pattern, and the weekday of Pesach. We replaced the raw day‑count comparisons with a `YearLength` enum (DEFICIENT/REGULAR/COMPLETE). A `yearLengthType` static method uses the existing `hasLongHeshvan` and `hasShortKislev` to determine the correct member.

The `YearType` enum was moved from `torah.py` to `HebrewDate.py` because the keviyah is a property of the calendar, not of the Torah‑reading logic. The final 14 codes — 7 ordinary and 7 leap — were verified against scholarly sources and are now members like `B_CH_G`, `B_SH_H`, `G_K_H`, etc. The `yeartype()` method is a long if‑chain exactly mirroring the old function but using the new enums, returning a `YearType` member directly (which has integer values 1–14, usable as an index into the reading tables).

## Compressing the reading tables

The original `torah2.py` contained two huge arrays with bare enum names. We compressed them into integer arrays where each list item is either a single `Parashah` number, a `HolidayReading` number, or a two‑element list for combined weeks. The final `READINGS` and `DIASPORA_READINGS` class variables inside `Torah` each have 14 rows (one per year type), each row a list of lists containing the reading for each Shabbat of that year type.

One critical correction: the old Diaspora tables had `PESAH_VIII` (63) in year types 4, 6, 9, 11, and 14, whereas the Israel tables had `PESAH_VII` (62) in those positions. This reflects the actual difference between Israel and Diaspora observance of the final days of Pesach. The compressed tables preserve this distinction.

## The Torah class

The `Torah` class now takes a `hebrewDate` and a `diaspora` flag. Its `readings` property determines the correct year, computes the week number from Shabbat Bereshith, looks up the year type via `HebrewDate.yeartype()`, and indexes into the appropriate table. It always returns a two‑element list: `[Parashah, None]` for a single portion, `[Parashah, Parashah]` for a combined week, or `[None, None]` for a holiday week (in which case the caller should consult the separate `holidayReading` property instead). The `holidayReading` property returns a `HolidayReading` member if the entry is a holiday replacement, otherwise `HolidayReading.NONE`.

The name‑lookup functions (`parashahNameEN/HE`, `holidayReadingNameEN/HE`) use simple arrays and direct indexing; they return an empty string for invalid IDs.

## Test harness and validation

We added a `__main__` block that iterates through every Shabbat of the current Hebrew year, prints the date, the reading(s), and the holiday name if applicable. Running it for 5786 showed all combined parashot in the correct positions, all special Shabbat labels aligning with the calendar, and all holiday readings correctly identifying Pesach, Sukkot, Rosh Hashanah, Yom Kippur, and Shavuot. The Diaspora version was validated by inspection against the known differences.
