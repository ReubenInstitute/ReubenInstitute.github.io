# 30 Jul 2026 – DeepSeek 3 Expert – C++ translation of the calendar library (strict port)

_Code, HebrewClock_

With the JavaScript library stable and the clock design locked, the next step was to move toward real hardware. The session took the entire ES6 module tree and translated it into plain C++ — no STL, no dynamic allocation, no `new`, and the constant `86400` banished from every file except `Time.cpp`. By the end, a Unix console program was printing civil and Hebrew calendars, and the code was ready to become firmware.

### Core `Date` class

The JavaScript `Date` class was rewritten in C++ with two new integer fields: `cjd` (Chronological Julian Day) and `jd` (astronomical Julian Day at midnight, computed as `cjd - 0.5`). The `epochDays()` and `julianDay()` methods were removed; the only public access to the day count was the `cjd` field itself.

Three constructors were provided: one from year, month, and day that computes `cjd` using the original pure‑integer algorithm with `serial + EPOCH` (EPOCH = 1721425); one from `cjd` that reverses the calculation; and a default constructor that initialises to 1/1/1. Arithmetic operators `+`, `-`, `+=`, `-=` work on `int` days via `cjd`, and `next()` and `prev()` were kept. `weekday()` returns Sunday=1 using `(cjd % 7 + 1) % 7 + 1`. Internal constants `DayOfWeek` and `GregorianMonth` were defined as plain `enum`s, used only inside the implementation to avoid magic numbers.

### `Calendar` and `HebrewCalendar`

The calendar grid classes were translated directly. `Calendar` stores a `Date days[31]` array and a `Date* dates[6][7]` pointer grid; `HebrewCalendar` does the same with `HebrewDate`. Both zero‑initialise the pointer grid with `nullptr`, then fill only the cells that belong to the month. The outer loop respects `rowCount`, exactly as the original. No dynamic allocation, no sentinels, no extra boolean arrays.

### `Time` and `DateTime`

`Time` was given three constructors: default to midnight, from `(hour, minute, second)`, and from total seconds — the only place where `86400.0` appears in the entire codebase, hidden inside `Time.cpp` as a `fmod` wrap. No `totalSeconds()` getter was exposed.

`DateTime` combines `Date` and `Time` with a default constructor, a `(Date, Time)` constructor, and a constructor from astronomical JD (converting to CJD and time via `floor(jd+0.5)`). Arithmetic operators on `DateTime` handle seconds: `newTime = time + seconds`, then detect day overflow by comparing the old and new `Time` hours — if `seconds > 0` and `newTime.hour < time.hour`, the date advances; if `seconds < 0` and `newTime.hour > time.hour`, the date retreats. No division by 86400 is used in the overflow logic. `DateTime::operator-(const DateTime&)` returns seconds, internally computing `dayDiff * 86400.0 + (timeSec - other.timeSec)`, but this constant is confined to `DateTime.cpp`, invisible to any Hebrew class.

### `HebrewDate`

The Hebrew date class was translated to use a raw day count from creation, with `EPOCH = 347996` so that `cjd = raw + EPOCH`. Internal conversion uses inline loops and temporary `HebrewDate` objects to get raw counts, exactly as the original JS. The `civilDate` member was kept as a `Date` in sync. `next()` and `prev()` operate via `civilDate.cjd ± 1`. `weekday()` delegates to `civilDate.weekday()`. No `epochDays()` or `julianDay` was exposed.

### `HebrewHoliday`

The holiday detection was translated as a class with an internal enum from `NONE` to `SHUSHAN_PURIM`. The constructor takes a `HebrewDate` and sets `id` according to the original logic, including Yom HaAtzmaut and Yom HaZikaron postponement rules. Holiday name arrays and `extern "C"` functions provide C‑linkage access to the names.

### `Geo` and `Astro` helpers

`Location` was written with a default constructor (Null Island) and a two‑parameter constructor, no initialiser lists. `Geo` holds the Earth radius and diaspora constants. `Astro.h` provides `J2000` and `EARTH_OBLIQUITY`.

### `Sun`

The `Sun` class uses `DateTime` members for `riseTime`, `setTime`, and `noonTime`. The constructor stores a `Location` and a `Date` (civil date), computes times via astronomical JD using `date.jd`. `dawnTime(deg)` and `duskTime(deg)` were added as per the JS refactor. All private helpers (`julianCycle`, `solarTransitJ`, etc.) were translated unchanged; the `RAD` constant is local.

### `Moon`

`Moon` stores a `Location`, a `DateTime datetime`, and `DateTime* rise`/`set` pointing to private members (allowing `nullptr`). `calculateTimes()` uses `NAN` for null hours instead of extra booleans. `calculateIllumination()` and all static helpers were translated directly. No dynamic allocation — the pointers point to member objects.

### `Custom`

The `DayDefinition`, `DawnCustom`, `MisheyakirCustom`, and `NightfallCustom` enums were defined as `enum class` to prevent name collisions. The `Custom` class holds integer values and a preset table with `setCustom()`.

### `LocalHebrewDate` (formerly `Yemama`)

The location‑ and custom‑aware Hebrew day class was translated, containing `HebrewDate hebrewDate`, `Location location`, and `Custom custom`. It computes halachic boundaries — `sunrise()`, `sunset()` from `Sun`, `dawn()`, `nightfall()`, `misheyakir()` using custom rules and `DateTime` arithmetic — and exposes `yemamaStart()`, `dayStart()`, `yemamaEnd()` based on `DayDefinition`. `dayLength()` and `nightLength()` return seconds via `DateTime::operator-`. All zmanim are computed as `dayStart() + fraction * dayLength()`. The `hour(const Time&)` method takes a civil `Time`, forms a `DateTime` from the Hebrew date’s civil date and that time, and computes the seasonal hour by comparing to `yemamaStart()`, `nightLength()`, and `dayLength()`. No `86400` or `jd` appear anywhere in this file.

### `extern "C"` name functions

All weekday, month, and holiday names were defined as `const char*` arrays and exposed through `extern "C"` functions, making the library callable from plain C.

### Build system and corrections

A `Makefile` was written to compile all `.cpp` files and link them. A test `app.cpp` was written that prints the civil July 2026 and Hebrew Av 5786 calendars, confirming that all calculations match the JavaScript behaviour. Several corrections were made during the session: removed accidental addition of a `raw` variable, removed `computeDays`, `totalSeconds()`, and `jd()` methods, eliminated all initialiser‑list syntax, fixed `weekday()` to match the original formula, fixed `Calendar` grid initialisation to avoid uninitialised pointers, and confirmed that `Moon` uses `NAN` for missing rise/set. The C++ library was self‑contained, compilable, and ready for display rendering.
