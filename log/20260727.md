# 27 Jul 2026 – DeepSeek 3 Expert – Yemama abstraction, off‑by‑one fix, and nightfall computation

_Code, HebrewClock_

What began as a mechanical update to wire a new `Zmanim` class into the clock became the session in which the Hebrew day’s boundaries were finally and permanently corrected. By the end, the class responsible for all halachic times had been renamed, its navigation logic rewritten to use Hebrew dates rather than civil days, and the central bug that had been shifting the night arc by one full cycle was dead.

### Initial state and the Zmanim class

A previous session had produced a new `Zmanim` class inside `HebrewDay.js`, designed to replace the old `HebrewDay` / `Day` / `DayTime` / `HebrewDayTime` tangle. The new class accepted a civil `DateTime`, a `Location`, and a `Custom`, and computed all zmanim lazily through getters. It already contained the corrected starting boundary — `dayEndYesterday` — but the `hour` getter still used astronomical sunrise and sunset rather than halachic boundaries, and the `yesterday` and `tomorrow` getters navigated by civil day rather than by Hebrew date. The old classes remained in the same file, decoupled from `Zmanim`, and the clock still used the old `HebrewDayTime`.

### The off‑by‑one bug

The original `HebrewDay` had calculated the night portion from `dayEnd` to `nextDayStart` — it looked forward to the next morning’s sunrise. This was one full cycle off. The correct Hebrew day runs from the previous evening’s sunset or nightfall to the current evening’s sunset or nightfall. The `Zmanim` class had already fixed this with `dayEndYesterday`, but the clock’s wiring still assumed the old wrong lengths, producing an incorrect night arc. The Hebrew day starts at the previous evening, not the next morning, and every downstream calculation depended on getting that right.

### Navigating between Hebrew days

To get the correct nightfall for the current Hebrew day under GRA, two Hebrew days cannot be assumed to have identical zmanim. The solution was to use `HebrewDate.previousDay` and `nextDay` to create a fresh instance of the halachic‑day class for the adjacent Hebrew date, using a civil noon time to avoid ambiguity. This created `previousYemama` and `nextYemama` accessors that removed all civil‑day confusion from cross‑day navigation.

### Naming overhaul: Yemama, dayStart, yemamaStart, yemamaEnd

The ambiguous word “day” was retired from the internal API. A new, precise vocabulary was locked:

- **Yemama** — the full halachic cycle, night followed by daylight. No direct English equivalent.
- **yemamaStart** — the beginning of that cycle, on the previous evening (sunset for GRA, nightfall for MA). Always on D‑1.
- **dayStart** — the start of halachic daylight, in the morning. Always on D.
- **yemamaEnd** — the end of the cycle, at the current evening’s sunset or nightfall. Always on D.

This eliminated every ambiguity. `dayLength` became the halachic day length from `dayStart` to `yemamaEnd`. `nightLength` became `dayStart` minus `yemamaStart`. The separation was clean and the arithmetic transparent.

### Nightfall computation

The nightfall getter was the central challenge. For GRA, nightfall of the current yemama occurs on the previous evening, shortly after sunset, and belongs to the previous Hebrew day’s halachic timeframe. For MA, it is the end of the current yemama. The initial attempt — calling `this.previousYemama.nightfall` — caused infinite recursion. Duplicating the entire switch block for GRA versus MA was rejected as messy.

The correct solution selected a local reference before a single switch block:

```javascript
let sunRef, refDayLength;
if (this.custom.dayDefinition === DayDefinition.GRA) {
    sunRef = this.sunYesterday;
    refDayLength = this.previousYemama.dayLength;
} else {
    sunRef = this.sun;
    refDayLength = this.daylightLength;
}
// single switch using sunRef and refDayLength
```

For GRA, `sunRef` used the previous day’s astronomical sunset and `refDayLength` used the previous yemama’s halachic day length. For MA, `sunRef` used the current day’s astronomical sunset and `refDayLength` used the astronomical daylight length — crucially *not* the halachic `dayLength`, which for MA depends on nightfall itself, creating a circularity. The astronomical length broke the loop. The `daylightLength` property was explicitly defined as `this.sunset.time.daySeconds() - this.sunrise.time.daySeconds()`.

### Fixing the hour getter

The `hour` getter had been using astronomical sunrise and sunset to decide day versus night. It was corrected to use halachic boundaries:

- Between `dayStart` and `yemamaEnd`: daytime, `hour = 12 + 12 * (elapsed / dayLength)`
- Between `yemamaStart` and `dayStart`: night, `hour = 12 * (elapsed / nightLength)`
- After `yemamaEnd`: the next night, `hour = 12 * ((now - yemamaEnd) / nextYemama.nightLength)`

This ensured the hour hand swept exactly along the halachic arcs and stayed aligned with the bands.

### Removing the old classes

`Day`, `DayTime`, `HebrewDay`, and `HebrewDayTime` were all superseded. They were removed from the active code, and `Yemama` became the single source of truth for every zman and boundary.

### Updating the clock

`NewHebrewClock.js` was renamed to `HebrewClock.js` and updated to accept a `Yemama` instance directly. All internal references were switched to the new property names. The solar night background continued to use astronomical sunrise and sunset, now obtained from `yemama.nextYemama.sunrise`. The test page was simplified to import only `Yemama` and `HebrewClock`, dropping all old class imports.

### Validation

Two tables were produced — one for GRA, one for MA — demonstrating that `yemamaStart` fell on D‑1, nightfall for GRA appeared on D‑1 after the start, nightfall for MA fell on D at the end with a different time because of the different reference lengths, and all daytime zmanim sat squarely on D. The off‑by‑one bug was conclusively resolved.

The session ended with a clean architecture: `Yemama` as the single halachic‑day class, `HebrewClock` as its SVG renderer, and the entire clock/calendar stack free of civil‑day confusion.
