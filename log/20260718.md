# 18 Jul 2026 – DeepSeek 3 – Hebrew and media libraries consolidated, Scriptures core cleaned, Studio split into two apps, Psalm pipeline production‑ready

*Code, Libraries, Studio, Web, PsalmSeries, ParashahSeries*

The session picked up where the previous day’s inventory left off: the Institute’s codebase was a tangle of mixed concerns, with Hebrew language utilities and styled text living inside the same folder as raw Sefaria data, and a monolithic Studio that handled both Psalms and Parashot in one process. By the end of the day, the foundation libraries were consolidated, the core scriptures browser was restored to a pure raw‑text viewer, the styled product layer was properly isolated, and the Studio was split into two independent applications—one of which is now fully operational for daily publishing.

### LIBS – a single home for foundation utilities

The first step was to pull `Hebrew.py` and `HebrewNumbers.py` out of the old `Scriptures/` folder. They had no business living next to the raw text classes; they are general‑purpose Hebrew processing tools used by the core library, the styled layer, and the Studio. We moved them into `/sdcard/Hebrew/` and added that folder to the global `PYTHONPATH`.

Later in the session, after examining the `Media.py` that had accumulated Studio‑specific output paths and an `Asset` class, we split the file. The pure utility functions (`get_duration`, `set_id3_tags`, `mp3towav`, `md5`, `fit`, and the dimension constants) were moved into the shared library folder. `Services.py` (ElevenLabs TTS and speech‑to‑speech wrappers) joined them. The folder was renamed to `/sdcard/LIBS/` and now contains exactly four files: `Hebrew.py`, `HebrewNumbers.py`, `Media.py`, and `Services.py`. Every future project imports from this one location.

### Scriptures core – structure and web browser cleaned

With the Hebrew utilities gone, the remaining `Scriptures/` folder still carried remnants of the old styled layer: `Bible.py` imported `BibleParashot` and created a `self.parashot` object. Both were removed. No other core class referenced the formatted editions.

The `db/` folder was retired. All CSV metadata files were moved into `csv/`, and the generated JSON text files into `json/`. `Source.py` was corrected to write `zohar-tikkunim.json` (not `tikkunei-zohar.json`) and to create the `json/` output directory if it does not exist. A clean build run regenerated all data and confirmed the pipeline is intact.

The single‑file web browser `app.py` was rebuilt. The Bible section now provides plain book‑list → chapter‑list → verse‑text navigation, matching the structure of the Mishnah and Zohar sections. The extra Mishnah mishnaya‑detail page was eliminated; all mishnayot now render directly on the chapter page. The Zohar Tikkunim attribute name was fixed (`tikkunei` → `tikkunim`). The result is a zero‑template browser that serves the entire raw corpus with no dependency on any styled content.

### StyledScriptures – the product layer formalised

The styled‑text layer—the Institute’s actual publishable content—was given a name and a home: `/sdcard/StyledScriptures/`. It contains `Parashot.py`, `Psalms.py`, and `Text.py` (the Markdown parser/serializer). The metadata files (`parashot.csv`, `episodes.csv`, `parashot.md`, `psalms.md`) were placed in the root of the folder, and all internal paths were updated to use `ROOT / "filename"`. The `.he.txt` files in the `text/parashot/` subdirectory were renamed to `.md` so that the `NarrationText` parser can find them.

Both modules were tested. `python Parashot.py` loads the first parashah and prints its styled text where the Markdown is available; otherwise it falls back to the raw Sefaria text. `python Psalms.py` prints the styled version of Psalm 117. The styled layer depends on the core `Scriptures` library for verse objects and on `LIBS` for Hebrew processing; the dependency direction is one‑way and clean.

The long‑term architectural debt—that the core classes currently mix structure and content loading from the Sefaria JSON files—was identified and recorded. The fix will require extracting structural metadata (chapter counts, page counts, article counts) into the CSV files so that the tree can be built without loading the full text. That is a future task; for now, all new code is written with the eventual separation in mind.

### AudioBible kept in the Studio

We considered extracting `AudioBible.py` into its own package, but decided to leave it inside the Studio folder, since only the Studio uses it. Its CSV file paths were fixed to resolve relative to `Path(__file__).parent` so that the library works regardless of the caller’s working directory. The `import HebrewNumbers` statement (unused) was removed.

### Studio split into two independent applications

The old monolithic `studio.py` was replaced by two separate Flask applications, both sharing the same flat `Studio/` directory:

- **`psalm-studio.py`** – Psalms only. The index route (`/`) renders the psalm list with full audio and video statistics. All psalm‑specific routes (detail, edit, audio marking, alignment, cloning, export) were moved here, with URLs flattened from `/bible/psalms/<number>` to simply `/<number>`.
- **`parashah-studio.py`** – Parashot only. The index route renders the parashot list. All parashah‑specific routes were moved here with similarly flattened URLs.

Both apps import the shared rendering modules (`Video.py`, `Audio.py`, `Image.py`, `Overlay.py`) directly from the flat folder. The `Asset` class and all output‑path constants (`PSALMS_FOLDER`, `PSALMS_PLUS_FOLDER`, `CINEMATIC_VIDEO_FOLDER`, `FADE_DURATION`, etc.) were extracted from the old Studio `Media.py` into `Studio/Asset.py`. The generic `Media.py` in `LIBS` now holds only the pure utility functions; the old Studio copy was deleted.

All psalm‑studio templates were updated to use the new flat URLs, and breadcrumb navigation was shortened accordingly. The Parashah side is structurally complete but depends on styled Markdown files that are not yet fully authored; it can be brought online when the text is ready.

### Live test

With `PYTHONPATH` set to `/sdcard/LIBS:/sdcard/Scriptures:/sdcard/StyledScriptures`, `psalm-studio.py` started without errors. Psalm 117 was edited in the browser, and covers (square, vertical, horizontal), audio (Library and Score), and video (Library, Score, Cinematic, horizontal variants) were exported successfully. The entire Psalm pipeline is operational and ready to resume daily publishing.

### Outcome

The Institute’s codebase is now organised into four clean layers with no circular dependencies:

- `/sdcard/LIBS/` – `Hebrew.py`, `HebrewNumbers.py`, `Media.py`, `Services.py`
- `/sdcard/Scriptures/` – core text classes, `app.py`, `csv/`, `json/`, `Source.py`
- `/sdcard/StyledScriptures/` – `Parashot.py`, `Psalms.py`, `Text.py`, metadata files, `text/`
- `/sdcard/Studio/` – `psalm-studio.py`, `parashah-studio.py`, `AudioBible.py`, `Asset.py`, `Audio.py`, `Video.py`, `Image.py`, `Overlay.py`, `templates-studio/`, `audio/`

The Psalm studio is production‑ready. The Parashah studio awaits fixing. The web browser serves the raw corpus to anyone who needs it. The foundation is solid, and the publishing silence can end.
